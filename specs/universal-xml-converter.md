### 4.3. Общий движок для новых подвкладок (6–11)

Нужен один модуль `XC` (свой `<script>`), его используют все новые подвкладки.

**Главный принцип — точечная правка текста.** Всё, чего пользователь не менял, должно остаться в файле байт в байт:
отступы, переводы строк `\r\n`, порядок атрибутов, `&quot;`, кодировка. Поэтому **не** сохраняй файл через
`DOMParser` + `XMLSerializer` (они теряют `<?xml … encoding="windows-1251"?>`, могут менять экранирование и пробелы).
Так же сделаны все вкладки в `index.html`.

1. **Чтение.** `readSources` (xml + zip) → `U.detectEncoding(bytes)` → `U.decodeBytes`. Запомни кодировку файла.
2. **Токенизатор с позициями.** Пройди текст и найди все теги `<…>` (пропуская `<?xml?>`, комментарии, CDATA).
   Для каждого элемента запомни:
   `id`, `name`, `path` (например `Документ › СвСчФакт › СвПрод › ИдСв › СвЮЛУч`), `start/end` открывающего тега,
   `outerStart/outerEnd` (вместе с закрывающим), `innerStart/innerEnd`, `selfClosing`, список атрибутов
   `{name, value (раскодированное), valStart, valEnd}` и, если внутри только текст, `text {value, start, end}`.
   Для проверки структуры можно параллельно прогнать `DOMParser` и при `parsererror` показать понятную ошибку
   «XML повреждён: …», но писать результат только через позиции.
3. **Правки.** Список `{start, end, newRaw}`. Значение экранируется при записи (`escapeXmlAttr` для атрибута,
   `escapeXmlText` для текста), показывается раскодированным (`decodeXml`). Правки применяются с конца файла к началу.
   Структурные операции (вставить/удалить/поменять местами блоки) — тоже правки по `outerStart/outerEnd`.
   После структурной операции текст **перечитывается токенизатором заново**.
4. **Конвейер каждой подвкладки:**
   `загрузка → преобразование (text → text) → редактор полей по результату → «Скачать»`.
   Преобразование даёт новый текст, редактор работает уже с ним. Так «можно поменять всё» работает одинаково везде.
5. **Запись.** `U.encodeText(text, encoding)`. Для windows-1251 **перед** записью проверь, что все символы
   кодируются: `encodeWindows1251` молча ставит `?`. Если есть некодируемые символы, покажи предупреждение со списком
   («символ „…“ в поле … не поддерживается в windows-1251») и не скачивай молча.
6. **Имя файла и ИдФайл** (функции из `reid`/`mark`):
   - `ИдФайл` = имя файла без `.xml`. Новый UUID v4 ставится **и в имя, и в `ИдФайл`**.
   - Строение имени: `ПРЕФИКС_<ИдПолучателя>_<ИдОтправителя>_<ГГГГММДД>_<UUID>[_хвост]`.
     Пример: `ON_NSCHFDOPPR` `_2BM-2311183230-231101001-201503270131044669475` (получатель, ТК Континент)
     `_2BM-6168094377-616801001-201912251039541320224` (отправитель, МЕОТИДА) `_20261028` (дата формирования файла)
     `_ddde1b10-…` (UUID) `_0_1_0_1_0_00` (служебный хвост УПД; у УКД хвоста нет).
   - ID участников ЭДО **нельзя собирать из ИНН/КПП в XML** (у МЕОТИДА в ID `616801001`, а в XML `КПП="774950001"`).
     Бери их только из имени исходного файла.
   - Разбор имени сделай отдельной функцией `parseEdoName(name)` → `{prefix, recipient, sender, date, uuid, tail}` и
     обратной `buildEdoName(parts)`. Если имя не разбирается, работай как `buildUuidName`: меняй только последний UUID.
7. **Общий редактор полей** (компонент, его используют подвкладки 6–11):
   - **Структурные карточки** (как в «УКД → иУКД (цены и коды)», но полнее): §8.1 — какие поля для УПД, §8.2 — для УКД.
   - **Блок «Все поля XML»** (свёрнут по умолчанию) — дерево всех элементов: путь, все атрибуты полями ввода,
     текст элемента полем ввода. Поиск по имени атрибута и значению. Подсветка изменённых полей.
   - **Один источник правды:** и карточки, и «Все поля XML» правят одни и те же атрибуты по `id` элемента и имени
     атрибута. Правка в одном месте сразу видна в другом.
   - Кнопки у полей: «↺ вернуть исходное» у каждого изменённого поля и «↺ Сбросить все правки».
   - Показ «Было → Стало» перед скачиванием: список изменённых полей (путь, атрибут, старое, новое).
8. **Коды маркировки в УПД** — `<ДопСведТов><НомСредИдентТов><НомУпак>…</НомУпак><КИЗ>…</КИЗ></НомСредИдентТов>`
   (бывает и `<НомСредИдентТов ИдентТрансУпак="…"/>`). Редактирование — как в `renderCodesBox` / `normalizeCodeLines` /
   `buildCodeGroup` (`index.html`): один код на строку, префиксы `КИЗ:`, `НомУпак:`, `ИдентТрансУпак:`, выбор тега по
   умолчанию, кнопка «Заменить на пачки». Коды содержат `<`, `'`, `"`, `;` (в образце `010460564806367521PPv;<VN`):
   в поле показывать раскодированными, в файл писать экранированными (`&lt;` и т. д.). Если блоков кодов у товара несколько,
   показывать каждый отдельно.
9. **Пересчёт сумм** (кнопка «Пересчитать», не автоматически без спроса):
   `СтТовБезНДС = round2(КолТов × ЦенаТов)`, `СумНал = round2(СтТовБезНДС × ставка)`,
   `СтТовУчНал = СтТовБезНДС + СумНал`, итоги `ВсегоОпл` — суммы по строкам. Ставки: `22%`, `20%`, `10%`, `7%`, `5%`, `0%`,
   `без НДС` (тогда `<СумНал><БезНДС>без НДС</БезНДС></СумНал>`), а также `22/122`, `20/120`, `10/110`.
   Проверка на образце: 16 × 629.59 = 10073.44; × 22% = 2216.16; итого 12289.60. Если итоги не сходятся с суммой
   строк, показывай предупреждение (жёлтое), но не исправляй сам.
10. **Скачивание и валидация** — как везде: ссылка-имя у карточки файла, «Скачать всё» (1 файл → XML,
    несколько → ZIP `<Название>_ГГГГММДД_ЧЧММ.zip` через `createZip`), кнопка «Валидация» открывает
    `https://www.diadoc.ru/docs/forms/validation-xml`. Пачка файлов и ZIP на входе — как в `reid`.
11. **Статусы и ошибки** — понятным русским текстом, как в существующих вкладках (`status ok/err/warn`).
    Ничего никуда не отправляется, всё в браузере.

| 1 | **УКД → иУКД**: две внутренние вкладки — «быстро» (новый UUID в имени и `ИдФайл`, строка `<ИспрКСчФ НомИспрКСчФ ДатаИспрКСчФ/>` после `<СчФ …/>`) и «цены и коды» (правка сторон, ТекстИнф, итогов, подписанта, товаров, НДС, кодов До/После, «Верные суммы из PDF/фото», правило направления увеличение/уменьшение) | На образце УКД результат совпадает с выдачей `index.html` (кроме UUID) |
| 2 | **СвВыбытияМАРК**: `<ТекстИнф Идентиф="СвВыбытияМАРК" Значен="3"/>` в `ИнфПолФХЖ1`, новый UUID, при необходимости дата `ДатаСчФ`/`ДатаДок` | То же |
| 3 | **ЛДНР без кодов**: удалить все `<НомСредИдентТов>` (НомУпак и КИЗ), новый UUID, хвост `_0_0_0_0_0_00` | То же; подсчёт «короба/блоки N, пачки КИЗ M» |
| 4 | **Замена ID**: новый UUID только в имени и `ИдФайл`, тип документа (УПД/ИУПД/УКД/иУКД), номера СчФ/КСчФ, ZIP на входе | То же; число UUID в файле не меняется |
| 5 | **Правильный УКД**: «Убрать одинаковое После» и «Коды До и После» (вариант А, `d.origText`) | То же |

Улучшения этих пяти — отдельной задачей и только с согласия владелицы. Сейчас — точная копия.

## 6. Новые подвкладки

### 6.1. УПД → иУПД (`iupd`)

**Зачем:** исправить уже отправленный УПД (тот же номер и дата документа, новое исправление).

**Эталон** — образец иУПД владелицы. Отличия иУПД от УПД (сверить с образцами!):
1. Внутри `<СвСчФакт НомерДок="…" ДатаДок="…">` **первым дочерним** элементом добавляется
   `<ИспрДок НомИспр="1" ДатаИспр="ДД.ММ.ГГГГ"/>` (отступ и перевод строки — как у соседних строк).
   Если `ИспрДок` уже есть (исправляем иУПД ещё раз) — не дублировать, а обновить: по умолчанию `НомИспр` + 1.
2. Новый UUID v4 в имени и `ИдФайл`, **хвост имени сохраняется** (`_0_1_0_1_0_00`, как в образце иУПД).
3. Дата формирования в имени файла (`_20261028_` → `_ГГГГММДД` сегодня) — галочка «Дата в имени = сегодня», включена
   (в образце иУПД дата в имени 20261103 = дата исправления).
4. `Документ@ДатаИнфПр` и `@ВремИнфПр` (`ЧЧ.ММ.СС`) = сейчас — галочка, включена (в образце `03.11.2026`, `11.04.36`).
5. `НомерДок` и `ДатаДок` **не меняются** (это исправление того же документа).

**Интерфейс:** поля «Номер исправления» (по умолчанию 1 или следующий) и «Дата исправления» (сегодня, `дд.мм.гггг`,
проверка формата); две галочки из пп. 3–4; ниже — общий редактор полей (§4.3 п. 7): можно поправить цены, количество,
коды, реквизиты (для этого иУПД обычно и делают).

**Проверка:** берём образец УПД, ставим НомИспр 1 и дату 03.11.2026 → структура совпадает с образцом иУПД
(сравнить построчно, разница допустима только в UUID, ВремИнфПр и в том, что владелица меняла вручную).
`detectDocType` из `reid` определяет результат как «ИУПД».

### 6.2. УПД → УКД (`upd2ukd`)

**Зачем:** сделать корректировочный документ к УПД (изменили цену или количество, вернули часть товара и т. п.).

**Как строить:** результат — **новый документ** по структуре образца УКД (`ON_NKORSCHFDOPPRMARK`). Возьми из образца
скелет: порядок элементов, `ВерсФорм`, `КНД`, `Функция`, `ПоФактХЖ`, `НаимДокОпр`, теги итогов и передачи.
Положи скелет в код шаблонной строкой **без персональных данных** образца. Данные заполни из УПД.

Соответствие полей (имена тегов УКД взяты из `parseProduct`/`parseAdvancedXml` в `index.html`; остальное сверить
с образцом УКД):

| УКД | Откуда |
|---|---|
| имя/`ИдФайл` | `ON_NKORSCHFDOPPRMARK_<получатель из имени УПД>_<отправитель из имени УПД>_<сегодня>_<новый UUID>` (хвоста нет, как в образце УКД) |
| `Документ@ДатаИнфПр/ВремИнфПр` | сейчас |
| `Документ@НаимЭконСубСост` | из УПД |
| `СвКСчФ@НомерКСчФ`, `@ДатаКСчФ` | ввод пользователя (по умолчанию: номер пустой — обязательное поле; дата — сегодня) |
| `СвКСчФ@КодОКВ` | `ДенИзм@КодОКВ` УПД (643) |
| `<СчФ НомерСчФ ДатаСчФ/>` | `СвСчФакт@НомерДок`, `@ДатаДок` УПД; если на входе иУПД — ещё реквизиты исправления (как в образце) |
| `СвПрод`, `СвПокуп` | копия блоков из УПД целиком |
| `ИнфПолФХЖ1` | копия из УПД (галочка «перенести», включена) |
| `СведТов@НомСтр`, `@НаимТов` | из УПД |
| `ОКЕИ_ТовДо` / `ОКЕИ_ТовПосле` | `ОКЕИ_Тов` / по умолчанию то же |
| `КолТовДо` / `КолТовПосле` | `КолТов` / ввод (по умолчанию то же) |
| `ЦенаТовДо` / `ЦенаТовПосле` | `ЦенаТов` / ввод (по умолчанию то же) |
| `НалСтДо` / `НалСтПосле` | `НалСт` / по умолчанию то же |
| `СтТовБезНДС@СтоимДоИзм/СтоимПослеИзм/СтоимУвел|СтоимУм` | `СтТовБезНДС` УПД / пересчёт / разница по модулю |
| `СумНалДо/СумНДС`, `СумНалПосле/СумНДС`, `СумНалРазн/СумУвел|СумУм` | `СумНал` УПД / пересчёт / разница |
| `СтТовУчНал@…` | аналогично по `СтТовУчНал` |
| `ДопСведТов@НаимЕдИзмДо/НаимЕдИзмПосле` | `НаимЕдИзм` |
| `НомСредИдентТовДо` / `НомСредИдентТовПосле` | коды из `НомСредИдентТов` товара УПД / по умолчанию те же, редактируются |
| `ИнфПолФХЖ2` | копия |
| `ВсегоУвел` / `ВсегоУм` | суммы по строкам (свои для увеличения и уменьшения) |
| передача / `ПередатДокум` (`РеквНаимДок`, `РеквНомерДок`, `РеквДатаДок`) | наименование, номер и дата УПД |
| `Подписант` | копия из УПД, редактируется |

Правила:
- **Направление по товару** — как `applyProductDirectionRule`: цена/стоимость выросла → только `СтоимУвел`/`СумУвел`,
  упала → только `СтоимУм`/`СумУм`. Строки без изменений — по образцу: выясни у владелицы, включать ли их
  (по умолчанию галочка «Только изменённые строки» включена, потому что в корректировку обычно идут только они).
- Быстрые действия над всеми строками: «Цена После = …» (одна новая цена), «Количество После = 0» (полный возврат),
  «Скидка N %».
- Кнопка «Пересчитать» (формулы §4.3 п. 9 для «После» и разниц).
- Редактор — как «УКД → иУКД (цены и коды)» плюс «Все поля XML».
- **Обязательно:** готовый файл проверяется в валидаторе Диадок. Пока владелица не подтвердит, что валидатор
  пропускает результат на её примере, считать подвкладку «бета» (пометка в интерфейсе).

### 6.3. УПД → новый УПД (`newupd`)

**Зачем:** сделать новый УПД на основе старого и поменять в нём что угодно.

1. Новый UUID в имени и `ИдФайл`; дата в имени = сегодня; `ДатаИнфПр/ВремИнфПр` = сейчас (галочки, включены).
2. Если в исходнике есть `<ИспрДок>`, по умолчанию удалить его (новый документ — не исправление), галочка.
3. Сверху — блок «Номер и дата документа» (тот же механизм, что в §6.4, со списком всех мест).
4. Ниже — **полный редактор** (§8.1): документ, стороны (продавец, грузоотправитель, грузополучатель, покупатель),
   документ отгрузки, валюта, доп. сведения, ТекстИнф, товары (все атрибуты, акциз, НДС, коды, ИнфПолФХЖ2), итоги,
   передача, основание, подписант. Плюс «Все поля XML».
5. Операции со строками товаров: **удалить строку** (с перенумерацией `НомСтр` по галочке), **дублировать строку**,
   **поднять/опустить**. После удаления/добавления предложить «Пересчитать итоги».
6. Операции с `ТекстИнф` и `ИнфПолФХЖ2`: добавить, удалить, изменить `Идентиф` и `Значен`.

### 6.4. УПД → новый номер и дата (`renum`)

**Зачем:** быстро поменять номер и дату УПД **во всех местах сразу**.

**Окно:** «Старый номер» (подставлен из `СвСчФакт@НомерДок`, можно исправить) → «Новый номер»;
«Старая дата» (из `СвСчФакт@ДатаДок`) → «Новая дата» (`дд.мм.гггг`).

**Поиск мест:** по токенизатору найди **все** атрибуты и тексты, значение которых **в точности равно** старому номеру или
старой дате, и покажи список с галочками:

| Путь | Атрибут | Сейчас | Галочка по умолчанию |
|---|---|---|---|
| `СвСчФакт` | `НомерДок` | 5431 | ✔ |
| `СвСчФакт` | `ДатаДок` | 28.10.2026 | ✔ |
| `ДокПодтвОтгрНом` | `РеквНомерДок` | 5431 | ✔ |
| `ДокПодтвОтгрНом` | `РеквДатаДок` | 28.10.2026 | ✔ |
| `СвПродПер › СвПер` | `ДатаПер` | 28.10.2026 | ✔ (дата отгрузки обычно = дате документа; владелица может снять) |
| любое другое совпадение (например, `ОснПер`, `СопрДокФХЖ`, `ТекстИнф`) | … | … | ☐ (совпадение может быть случайным) |

Правила:
- Сравнение точное (`5431` не совпадает с `5431А`, `15431`).
- Галочки «вкл. все / выкл. все». Перед скачиванием — «Было → Стало» по отмеченным.
- Дополнительно (галочки, включены): новый UUID в имени и `ИдФайл`, дата в имени файла = сегодня,
  `ДатаИнфПр/ВремИнфПр` = сейчас.
- Для УКД (бонус, если просто): то же для `СвКСчФ@НомерКСчФ/ДатаКСчФ` и связанных реквизитов.
- Пачка файлов: для пачки — только автозамена по таблице «по умолчанию», без ручного списка, и номер для каждого
  файла свой (поле в карточке файла).

### 6.5. Поменять местами Продавца и Покупателя (`swap`)

**Зачем:** обратная поставка, когда клиент не может сам сделать УПД: документ выглядит так, будто покупатель продаёт нам.

**Кнопка «⇄ Поменять местами»** делает всё сразу, потом всё можно поправить в полях.

Что меняется:

| Что | Как |
|---|---|
| `СвПрод` ↔ `СвПокуп` | Меняется **всё содержимое** блоков и атрибуты открывающего тега (`ОКПО` и др.), имена тегов остаются. Тип стороны (ЮЛ `СвЮЛУч` / ИП `СвИП` / ФЛ) переезжает вместе с содержимым. Адреса тоже |
| `ГрузОт` / `ГрузОтпр` ↔ `ГрузПолуч` | По умолчанию поменять местами содержимое (товар едет обратно). В образце грузоотправитель — ИП Маркарян (Ставрополь), грузополучатель — ТК Континент. Если у `ГрузОт` стоит `<ОнЖе>он же</ОнЖе>`, то после обмена «он же» относится к новому продавцу, а в `ГрузПолуч` нужно вписать прежнего продавца явно. Галочки: «Грузоотправитель = новый продавец (он же)», «Грузополучатель = новый покупатель». Поля редактируются |
| `Документ@НаимЭконСубСост` | наименование нового продавца (`НаимОрг` или «ИП Фамилия И. О.») |
| Имя файла и `ИдФайл` | **получатель ↔ отправитель** (ID участников меняются местами), новый UUID, дата в имени = сегодня, хвост сохраняется |
| `Подписант` | Это должен быть человек **нового продавца** (клиента). Поля `Должн`, `Фамилия`, `Имя`, `Отчество`, `СпосПодтПолном` (и другие, что есть в образце) очищаются и становятся обязательными; пока не заполнены — «Скачать» неактивна. Кнопка «оставить прежнего подписанта» для особых случаев |
| `ИнфПолФХЖ1 › ТекстИнф Идентиф="МЧД"` | Это доверенность подписанта МЕОТИДА — после обмена **удаляется** (галочка, включена) или заменяется на МЧД клиента (поле) |
| `ТекстИнф Идентиф="мил_OrderId"` | внутренний ID заказа МЕОТИДА — по умолчанию удаляется (галочка) |
| `ИнфПолФХЖ2` (`мил_guid`, `штрихкод`) | по умолчанию оставить (галочка «удалить внутренние мил_guid») |
| `ДопСвФХЖ1 › СопрДокФХЖ` | оставить, поля редактируются |
| `ДокПодтвОтгрНом`, номер и дата документа | Встроить блок из §6.4: у обратного УПД будет свой номер и дата (номер документа клиента) |
| `СвПродПер › СвПер` (`СодОпер`, `ДатаПер`), `ОснПер` (договор) | остаются, редактируются |
| Товары, цены, коды | не меняются, редактируются в общем редакторе |

Интерфейс: слева «Было» (продавец, покупатель, грузоотправитель, грузополучатель, подписант — карточками),
по центру кнопка «⇄ Поменять местами», справа «Стало» с полями. Повторное нажатие возвращает как было (обмен обратимый,
пока не скачали). Ниже — общий редактор и «Все поля XML».

**Проверка:** на образце УПД после обмена `СвПрод` содержит ТК Континент (ИНН 2311183230, КПП 231101001,
адрес Краснодар), `СвПокуп` — МЕОТИДА (ИНН 6168094377, КПП 774950001, адрес Ростов-на-Дону), имя файла начинается с
`ON_NSCHFDOPPR_2BM-6168094377-…_2BM-2311183230-…`. Двойной обмен без правок возвращает исходные блоки байт в байт.

### 6.6. Редактор XML (все поля) (`raw`)

Любой XML (УПД, иУПД, УКД, иУКД и другие). Загрузка → «Все поля XML» во весь экран (дерево, поиск, правка любого
атрибута и текста) + галочка «Новый UUID в имени и ИдФайл». Показ типа документа (`detectDocType`).
Без изменений файл должен сохраняться **байт в байт**.

## 7. Что значит «можно менять абсолютно всё» (по выделениям владелицы на скриншотах)

Владелица выделила жёлтым всё, что хочет менять. Минимум полей в структурных карточках УПД:

- `Файл@ИдФайл` (через UUID), `Документ@ДатаИнфПр`, `@ВремИнфПр`, `@НаимЭконСубСост`, `@Функция` (только просмотр);
- `СвСчФакт@НомерДок`, `@ДатаДок`; `ИспрДок@НомИспр`, `@ДатаИспр`;
- **стороны** (`СвПрод`, `ГрузОтпр`, `ГрузПолуч`, `СвПокуп`): `ОКПО`; ЮЛ — `НаимОрг`, `ИННЮЛ`, `КПП`; ИП — `ИННФЛ`,
  `ФИО@Фамилия/Имя/Отчество`; адрес — `АдрИнф@КодСтр`, `@НаимСтран`, `@АдрТекст` (и `АдрРФ`, если встретится);
  переключатель типа стороны ЮЛ ↔ ИП (с перестройкой `ИдСв`);
- `ДокПодтвОтгрНом@РеквНаимДок`, `@РеквНомерДок`, `@РеквДатаДок`;
- `ДенИзм@КодОКВ`, `@НаимОКВ`;
- `ДопСвФХЖ1 › СопрДокФХЖ@РеквНаимДок`, `@РеквНомерДок`, `@РеквДатаДок`;
- `ИнфПолФХЖ1 › ТекстИнф` — все строки (`Идентиф`, `Значен`), добавить/удалить;
- **товары** (`СведТов`): `НомСтр`, `НалСт`, `НаимТов`, `ОКЕИ_Тов`, `НаимЕдИзм`, `КолТов`, `ЦенаТов`, `СтТовБезНДС`,
  `СтТовУчНал`; `ДопСведТов@ПрТовРаб`; коды `НомУпак`/`КИЗ`; `Акциз` (`БезАкциз` или сумма); `СумНал › СумНал`
  (или `БезНДС`); `ИнфПолФХЖ2` (`мил_guid`, `штрихкод` и др.);
- итоги `ВсегоОпл@СтТовБезНДСВсего`, `@СтТовУчНалВсего`, `СумНалВсего › СумНал`;
- `СвПродПер › СвПер@СодОпер`, `@ДатаПер`; `ОснПер@РеквНаимДок`, `@РеквНомерДок`, `@РеквДатаДок`;
- `Подписант@СпосПодтПолном`, `@Должн`, `ФИО@Фамилия/Имя/Отчество`.

Всё, чего нет в карточках, доступно в «Все поля XML». Отображение — как в «цены и коды»: карточки сторон и
товаров с цветной левой полосой (`color-0…5`), сетка полей `fields three/four`, поля кодов на всю ширину,
`textarea` с `white-space:pre-wrap; overflow-wrap:anywhere; word-break:break-all`.

## 8. Справка по структуре (сверить с образцами)

### 8.1. УПД (`ON_NSCHFDOPPR`, ВерсФорм 5.03, КНД 1115131, Функция СЧФДОП) — по скриншотам

```
Файл ИдФайл ВерсФорм ВерсПрог
└ Документ КНД ВремИнфПр ДатаИнфПр Функция ПоФактХЖ НаимДокОпр НаимЭконСубСост
```

### 8.3. Мелочи, на которых легко ошибиться

- Атрибут `ДатаДок` ищи с ведущим пробелом (`\sДатаДок=`), иначе зацепишь `РеквДатаДок` (так сделано в `getDocDate`).
- Значения в файле экранированы: `НаимОрг="ООО &quot;МЕОТИДА&quot;"`. Показывать `ООО "МЕОТИДА"`, писать обратно `&quot;`.
- Перевод строки бери из файла (`\r\n` или `\n`), отступ — у соседней строки.
- UUID в файле УПД встречается десятки раз (в образце 47 — `мил_guid` и др.). Менять UUID **только** в `ИдФайл` и имени.
- Новый UUID — `generateUUIDv4(used)`, уникальный в пачке.
- Дата — строго `дд.мм.гггг`, время `ВремИнфПр` — `ЧЧ.ММ.СС`.
- Числа пишутся с точкой, суммы — 2 знака; цену и количество не округлять, если пользователь ввёл больше знаков.
- Префиксы `перв_`, `иУКД_` в имени срезаются (`stripKnownPrefix`), как в УКД.
